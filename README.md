# artifacts_mmo

A client/server setup for playing [ArtifactsMMO](https://www.artifactsmmo.com/) by hand.
The server is a thin TypeScript layer over the game API; clients (a webapp, or anything
else) talk to the server and share a contract package with it.

## Architecture

```
packages/
  shared/   @artifacts/shared  — the contract: TypeBox schemas (problem details, DTOs) with
                                 Static<>-derived types, plus the server's generated
                                 OpenAPI spec (spec/openapi.yaml). Importable by any
                                 TS client; only dependency is typebox.
  server/   @artifacts/server  — Fastify app wrapping the ArtifactsMMO API.
                                 Owns the game token; clients never see it.
  webapp/   @artifacts/webapp  — Vue 3 client (Vite). Talks to the server through a
                                 REST client generated from the shared spec.
```

Yarn workspaces link `@artifacts/shared` into consumers; it's imported as TS source
directly (no build step anywhere — everything runs through tsx/Vite-style tooling).

## Setup

```sh
yarn install
mkdir -p ~/.config/artifacts_mmo && echo '{ "artifactsToken": "..." }' > ~/.config/artifacts_mmo/config.json
# paste your token (https://artifactsmmo.com/account) into that file
yarn generate    # regenerate the ArtifactsMMO client stubs from the vendored spec
```

The API token is read from `~/.config/artifacts_mmo/config.json` (see `packages/server/src/config.ts`).
Other settings (e.g. `PORT`) come from the environment; an optional `packages/server/.env` is loaded if present.

## Scripts (run from the repo root)

| Script           | What it does                                                           |
| ---------------- | ---------------------------------------------------------------------- |
| `yarn dev`       | Run the server with watch/reload (tsx)                                 |
| `yarn dev:web`   | Run the webapp dev server (Vite; proxies `/api` to the server)         |
| `yarn build:web` | Typecheck + production-build the webapp                                |
| `yarn start`     | Run the server once                                                    |
| `yarn spec:fetch`| Refresh the vendored spec `packages/server/spec/openapi.json` (network) |
| `yarn generate`  | Regenerate `packages/server/generated-src/artifactsmmo/` from the spec |
| `yarn spec:generate` | Regenerate our own spec `packages/shared/spec/openapi.yaml` from the server's route schemas |
| `yarn typecheck` | Typecheck every workspace                                              |
| `yarn test`      | Run the server's Vitest suite                                          |

After changing a route or shared schema: `yarn spec:generate`, then
`yarn workspace @artifacts/webapp generate`, and commit both outputs.

## Logging

The server logs one readable line per request and per upstream game-API call.
`LOG_LEVEL=debug` adds Jersey-style wire dumps of both directions (start line,
headers with `authorization`/`cookie` redacted, body capped at 2000 chars).
Output is pretty-printed unless `NODE_ENV=production`; force with `LOG_PRETTY=0/1`.

## Conventions

- **Contract first**: the TypeBox schemas in `@artifacts/shared` are the single source
  of truth for the server's API (ADR-0003). Server routes declare them as `response`
  schemas — Fastify then strips out-of-schema fields from responses — and routes must
  live in plugins so `yarn spec:generate` can see them. Clients consume the contract
  via the generated spec, not by duplicating shapes.
- **`packages/server/src/api/client.ts`** — configures the generated game-API client
  (base URL + auth) and re-exports one typed stub per endpoint. Import stubs from this
  module (e.g. `getMyCharactersMyCharactersGet()`), never from `@generated` directly.
- **`generated-src/`** — code generated by a pinned `@hey-api/openapi-ts`: the game-API
  client inside the server (from `packages/server/spec/openapi.json`) and the webapp's
  REST client (from `packages/shared/spec/openapi.yaml`). Never edit by hand; committed;
  linters skip it. After game updates run `yarn spec:fetch` then `yarn generate`.
- Path aliases in server and webapp: `@/*` → `src/*`, `@generated/*` → `generated-src/*`.

## Adding a client

1. Scaffold it under `packages/<name>` with a tsconfig extending `../../tsconfig.base.json`.
2. `yarn install` to link workspaces.
3. Generate a typed client from `packages/shared/spec/openapi.yaml` (mirror the webapp's
   pinned `openapi-ts` setup), or for TS clients import schemas from `@artifacts/shared`.
   In dev, proxy `/api` to the server port (see `packages/webapp/vite.config.ts` — the
   server registers routes at the root, so the proxy strips the `/api` prefix).
